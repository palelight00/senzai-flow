# 洗剤記録 — 浴槽自動洗浄

浴槽の自動洗浄機で使うバスマジックリンの**洗剤量を手早く記録する**ためのWEBアプリです。
最終的な目的は、記録をためて「**冬季の寒い時期に1回あたりの洗剤使用量が公称値（25ml）より増えるのか**」を、後日 気象条件・外気温と突き合わせて分析することです。

このフェーズの最優先は「記録のしやすさ」。アプリを開いて**最少タップ**で記録できることを重視しています。

## 特徴

- **ビルド不要の静的サイト**（素の HTML/CSS/JS）。GitHub Pages で公開し、Safari など各種ブラウザから直接アクセスできます。
- **データはブラウザ内（localStorage）にのみ保存**。サーバには送りません。
- **JSON / CSV で書き出し・JSON で読み込み**ができ、バックアップ・端末間移行が可能。
- **PWA 対応**。iPhone の「ホーム画面に追加」でアプリのように使え、オフラインでも記録できます。
- **分析タブ**。平均洗剤使用量（全体/年/季節/月）、各種グラフ、外気温との相関を表示（外部ライブラリ不使用の自作SVGグラフ）。

## 記録できるイベント

| ボタン | 意味 |
|---|---|
| 洗剤追加（×1 / ×2） | 詰め替え 300ml ×1（+300ml）または ×2（+600ml）を追加 |
| low シグナル | 残量が 350ml 未満になった |
| min シグナル | 残量が 150ml 未満になった |
| 洗浄休み | その日は洗浄しなかった（消費なし） |

- 通常は「1日1回洗浄」と仮定し、例外（洗浄休み）とシグナル・追加だけを記録します。
- ヘッダーに**推定残量**と**シグナル状態**を表示します（記録時のフィードバック用の概算）。
- 日付を選べば**過去日の記録（事後入力）**ができ、履歴から**編集・削除**もできます。
- 各記録には任意で**備考**を付けられます（外気温メモ・2回洗浄など）。

## 使い方

1. 公開URL（`https://palelight00.github.io/senzai-flow/`）を Safari で開く。
2. 共有メニュー →「**ホーム画面に追加**」でアプリ化（任意）。
3. 該当ボタンをタップして記録。過去分は上部の日付を変えてから記録。
4. 「データ」タブから定期的に**JSON で書き出し**て保管。

### 過去データの読み込み

過去の記録は**プライバシーのためリポジトリには含めていません**。
別途お渡しする `senzai-flow-records.json` を端末に保存し、アプリの
「データ」→「JSON ファイルを選ぶ」→「追加（マージ）」で取り込んでください。

## 分析タブ

「分析」タブでは、記録から**1回あたりの洗剤使用量（ml/回）**と **1日あたり（ml/日）** を算出して集計・可視化します。

- **算出方法**: `low`(350ml)/`min`(150ml)/`追加後`の残量を起点に、区間の消費量 ÷ 洗浄回数（1日1回洗浄・休みを除外と仮定）で求めます。
  両端が実測シグナル（low/min）の区間は **観測（●・バイアスなし）**、追加を含む区間は **推定（○・追加時の残量仮定に依存）** と区別します。
  集計は**洗浄回数加重平均**（Σ消費 ÷ Σ洗浄回数）で、区間の切り方に依存しません。
- **集計単位**: 全体 / 年 / 季節（気象学的: 冬12-2・春3-5・夏6-8・秋9-11）/ 月 を切り替え。
- **グラフ**: ①月/季節/年の棒グラフ（公称25ml基準線つき）②ml/回の時系列 ③ml/回 vs 気温の散布図＋回帰直線＋相関係数 ④月次の使用量×気温オーバーレイ。

### 気温データ

外気温との相関を見るため、任意の地点の日別 最高/最低/平均気温を取り込めます。

- **観測地点の設定**: 最初に分析タブで **地点名・緯度・経度** を設定します（「現在地から入力」ボタンも使えます）。
  地点はリポジトリには含まれず、**この端末の localStorage にのみ**保存されます。緯度経度は小数2桁（約1km）に丸めて保存し、住居が特定できる精度では扱いません。
- **自動取得**: 「（地点名）の気温を自動取得」ボタンで [Open-Meteo](https://open-meteo.com/) の無料・鍵不要の過去気象APIから取得します（ブラウザから直接通信。アーカイブの仕様上、直近約5日は未掲載）。
- **CSV読み込み**: 気象庁などのCSVも読み込めます。`date,min,max,mean` 形式のほか、気象庁形式（`年月日`/`最高・最低・平均気温(℃)`・`2025/1/13` 形式・欠測 `×`/空）にも対応。
- 気温データも JSON 書き出しに含まれ、バックアップ・移行できます。

## GitHub Pages での公開手順

1. このリポジトリの **Settings → Pages** を開く。
2. **Source** を「**GitHub Actions**」に設定（1回だけ）。
3. `main`（または `claude/lucid-wozniak-5yDXf`）に push するとワークフロー
   （`.github/workflows/pages.yml`）が走り、自動でデプロイされます。
4. 数十秒後に公開URLへアクセスできます。

### 公開時のプライバシー

個人利用のアプリなので、検索エンジンには載せない設定にしています。

- `index.html` に `<meta name="robots" content="noindex, nofollow">` を入れてあります。**実際に効くのはこちら**です。
- `robots.txt` も置いてありますが、GitHub Pages のプロジェクトサイト（`/senzai-flow/` 配下）ではクローラに参照されません（`robots.txt` はドメイン直下のみ有効）。独自ドメインへ移した場合の保険です。
- いずれも**URLを直接知っている人のアクセスは防げません**。見せたくない場合はリポジトリを Private にしてください（Private リポジトリからの Pages 公開には有料プランが必要です）。
- 記録データはサーバに送られず、端末の localStorage にのみ保存されます。

## データ形式（JSON）

```jsonc
{
  "schemaVersion": 1,
  "config": { "tankCapacity": 850, "refillUnit": 300,
              "lowThreshold": 350, "minThreshold": 150, "nominalPerWash": 25 },
  "events": [
    { "id": "...", "type": "add", "date": "2025-01-06", "amount": 600,
      "note": "", "createdAt": "2025-01-06T12:00:00.000Z" }
  ],
  "weather": {
    "schemaVersion": 1,
    "location": { "name": "○○市", "lat": 35.68, "lon": 139.77 },
    "daily": { "2025-01-06": { "min": -2.1, "max": 3.4, "mean": 0.6 } }
  }
}
```

`type` は `add` / `low` / `min` / `rest`。`amount`（300 または 600）は `add` のときのみ。
日付は端末ローカルの暦日（`YYYY-MM-DD`）で保持します。
`weather` は分析用の気温データ（任意。localStorage では別キー `senzai-flow/weather/v1` に保存し、書き出し時に同梱）。
